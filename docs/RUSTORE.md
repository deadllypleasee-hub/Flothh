# Подготовка к RuStore

Текущая версия 0.1.1 — тестовый прототип. Эта инструкция готовит дальнейший выпуск, не подтверждает готовность к модерации. Удалённая публикация в этой сессии не выполнялась.

1. Установить debug APK на целевые ARM64 устройства. Пройти все миссии, обязательный сценарий редактора, мультитач, паузу/возврат, сворачивание/восстановление и сохранения. Провести длительный бой, измерить FPS, память, нагрев и расход батареи. Исправить критические проблемы из `STATUS.md`.
2. Создать постоянный release keystore. Сохранить несколько защищённых резервных копий. Подписывать все будущие обновления тем же ключом; debug APK для магазина не использовать.
3. Выбрать постоянный package ID. Сейчас `com.fortisgames.deepwaters`; убедиться, что он принадлежит вашему продукту и не занят. Увеличить versionCode для новой версии. Проверить актуальные требования RuStore к APK/AAB, target API, архитектурам и подписи в кабинете разработчика.
4. Настроить GitHub Secrets по `ANDROID.md`, запустить **Signed Android release candidate** и проверить полученный APK через `apksigner verify --verbose` и установку на чистое устройство. Обязательно проверить обновление поверх ранее подписанной release-версии.
5. Зарегистрировать разработчика в [RuStore Console](https://console.rustore.ru/), подготовить профиль и подтверждение прав на название/бренд, если требуется.
6. Создать карточку приложения: «FORTIS: DEEP WATERS», FORTIS GAMES, русское описание, жанр, контакт поддержки, возрастной рейтинг, иконка, реальные скриншоты и перечень поддерживаемых устройств. Не рекламировать ещё не реализованные функции и не использовать тестовые кадры как обещание коммерческой графики.
7. Подготовить сведения о данных и разрешениях на основе финального билда. Сейчас приложение офлайн, без аналитики, рекламы и аккаунта; прогресс хранится локально, единственное запрошенное разрешение — вибрация. Повторно проверить манифест перед отправкой, указать актуальную политику конфиденциальности и требования магазина.
8. Приложить лицензии и атрибуции. Геометрия, иконка, эффекты и звуки в текущем проекте процедурные; движок Godot распространяется по MIT, см. `THIRD_PARTY.md`. При добавлении ассетов фиксировать автора и лицензию каждого.
9. Загрузить подписанный release APK, заполнить заметки версии и данные модерации. Сначала использовать доступный в кабинете тестовый/ограниченный канал. Проверить скачивание и запуск именно магазинной сборки, затем решать вопрос публичного выпуска.

Актуальные правила и способы загрузки уточнять по [официальной документации RuStore](https://www.rustore.ru/help/developers). Эта локальная инструкция не заменяет требования, действующие на дату публикации.
